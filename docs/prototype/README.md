# نمونه اولیه رابط کاربری GaranTech

این پوشه یک نمونه اولیه تعاملی و مستقل برای بازبینی جریان‌های رابط کاربری سامانه GaranTech دارد.

## اجرا
فایل `index.html` را مستقیماً در مرورگر باز کنید. به نصب وابستگی یا سرور توسعه نیاز نیست.

## مستندات
- [جریان‌های کاربری و وضعیت‌های رابط کاربری](ui-flows.md)

## صفحات
- مشتری: ثبت درخواست، پیگیری، جزئیات، تصمیم درباره پیشنهاد هزینه و لغو
- کارشناس خدمات: داشبورد، ثبت دریافت فیزیکی، بازرسی و پیشنهاد هزینه
- تعمیرکار: داشبورد، ثبت عملیات تعمیر و آزمون نهایی
- مدیر سامانه: داشبورد و مدیریت کارکنان

## قواعد مهم گردش‌کار
- ثبت درخواست مشتری بدون حساب کاربری است.
- پیگیری و اقدامات مشتری روی درخواست موجود به کد رهگیری و شماره تلفن ثبت‌شده نیاز دارند.
- بازرسی تا پیش از ثبت دریافت فیزیکی دستگاه مجاز نیست.
- بازرسی یک یا چند عیب با عنوان و شرح را می‌پذیرد و اقدام پیشنهادی را ثبت می‌کند.
- در صورت مغایرت دستگاه تحویلی، کارشناس می‌تواند مشخصات دستگاه را در فرایند دریافت اصلاح کند.
- برند دستگاه اختیاری است؛ نوع و مدل الزامی‌اند.
- پیشنهاد هزینه فقط پس از تکمیل بازرسی و برای `NOT_ELIGIBLE` قابل ثبت است.
- گارانتی واجد شرایط مستقیماً به `READY_FOR_REPAIR` می‌رود و پیشنهاد هزینه ندارد.
- شروع تعمیر فقط از `READY_FOR_REPAIR` ممکن است؛ پس از شروع تعمیر لغو مجاز نیست.
- عملیات تعمیر ثبت و در همان صفحه نمایش داده می‌شود.
- مدیر می‌تواند حساب نمایشی کارمند را با نام، شماره تماس، نام کاربری، نقش و رمز اولیه ایجاد کند؛ نمونه اولیه رمز خام را نگهداری نمی‌کند.
- آزمون ناموفق درخواست را در `IN_REPAIR` نگه می‌دارد؛ آزمون موفق آن را `COMPLETED` می‌کند.
- توضیح آزمون برای FAILED اجباری و برای PASSED اختیاری است.
- واحد پول مبالغ IRR (ریال ایران) است و مبلغ پیشنهاد باید مثبت باشد.
- نمای مشتری فقط اطلاعات مجاز BR-06 را نشان می‌دهد، نه تاریخچه کامل یا یادداشت‌های داخلی.
- فرم کارکنان فیلدهای نام، شماره تماس، نام کاربری، نقش و رمز اولیه را می‌گیرد؛ نمونه اولیه رمز خام را ذخیره نمی‌کند.

## وضعیت‌ها و محدودیت‌ها
این نمونه وضعیت‌های اولیه/خالی، خطای اعتبارسنجی، درخواست ناموفق/یافت‌نشده، مسدودشدن گردش‌کار، غیرفعال بودن عملیات نامعتبر، پیام موفقیت و تأیید لغو را نمایش می‌دهد. چون نمونه به API متصل نیست، وضعیت بارگذاری شبکه در این مرحله وجود ندارد؛ رفتار آن برای نسخه متصل به API در `ui-flows.md` مشخص شده است.

داده‌ها نمایشی و فقط در حافظه مرورگر هستند. API، پایگاه داده، احراز هویت واقعی، کنترل دسترسی سمت سرور، ذخیره‌سازی پایدار و آزمون خودکار در این PR پیاده‌سازی نشده‌اند. انتخاب نقش صرفاً برای مشاهده صفحات مختلف است و نباید به‌عنوان کنترل امنیتی تلقی شود.
