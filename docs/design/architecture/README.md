# طراحی معماری سامانه GaranTech

> نسخه: پیش‌نویس طراحی اولیه  
> وضعیت: آماده بازبینی تیمی  
> زبان مستند: فارسی

## هدف

این پوشه معماری اولیه GaranTech را پیش از شروع پیاده‌سازی مستند می‌کند. طراحی بر اساس سند نیازمندی‌های نرم‌افزار، موارد کاربرد، نمودار فعالیت و مدل داده منطقی پروژه تهیه شده است.

معماری فعلی یک **سامانه وب با یک برنامه فرانت‌اند، بک‌اند یکپارچه ماژولار مبتنی بر FastAPI و پایگاه داده PostgreSQL** را توصیف می‌کند. انتخاب فناوری فرانت‌اند، ORM و ابزار Migration هنوز انجام نشده است.

## خلاصه معماری مصوب اولیه

- مشتری مستقیماً از طریق رابط وب با سامانه تعامل می‌کند و برای ثبت درخواست حساب کاربری ندارد.
- پیگیری درخواست مشتری با کد رهگیری و شماره تلفن ثبت‌شده انجام می‌شود.
- کارکنان از طریق حساب کاربری سازمانی وارد می‌شوند.
- فرانت‌اند یک برنامه وب واحد با رابط‌های متناسب با نقش‌ها است.
- بک‌اند یک **Modular Monolith** است؛ ماژول‌ها مرز مسئولیت مشخص دارند اما به‌صورت سرویس‌های مستقل مستقر نمی‌شوند.
- پایگاه داده از نوع رابطه‌ای و DBMS انتخاب‌شده PostgreSQL است.\n- فریم‌ورک بک‌اند انتخاب‌شده FastAPI است.
- بک‌اند به چهار لایه Presentation، Application، Domain و Infrastructure تقسیم می‌شود.
- تغییر وضعیت درخواست از یک مؤلفه مرکزی عبور می‌کند.
- کنترل مجوزها در سمت بک‌اند انجام می‌شود.
- تغییرات داده‌ای مرتبط باید در تراکنش واحد و سازگار ذخیره شوند.

## نکات و محدودیت‌ها

- این مستند، طراحی منطقی اولیه است؛ انتخاب FastAPI و PostgreSQL قطعی شده، اما به معنی پیاده‌سازی آن‌ها نیست.
- جزئیات API، ساختار فیزیکی پایگاه داده، استقرار، زیرساخت، پشتیبان‌گیری و مانیتورینگ در این مرحله طراحی نشده‌اند.
- نمودارها با Mermaid نوشته شده‌اند تا در GitHub قابل مشاهده و نگهداری باشند.
- تصمیم‌های این سند باید پیش از پیاده‌سازی توسط اعضای تیم بازبینی شوند.
